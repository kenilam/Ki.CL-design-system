## Match the urgency

Make the feedback as prominent as the moment needs. A saved setting needs a quiet line of text next to it. A failed payment needs an error the person can't miss. Something that can't be undone needs a dialog that asks first. If everything interrupts, people learn to dismiss it without reading.

## More than one channel

Never let colour carry the message alone. Pair it with words, and an icon where it helps, so it still works for someone who can't tell red from green, has the screen dimmed, or is listening with a screen reader. `Status` gives each level an icon and text as well as a colour.

## Announce without moving focus

Text that appears on its own has to be announced, or a screen reader user may never know. Put it in a live region that's on the page before the message arrives: `role='status'` waits for a pause, and `role='alert'` speaks straight away. Keep `alert` for errors, since it interrupts whatever is being read.

## Show progress where it started

Put a loading state on the control that started the action, and change its label to say what's happening. A spinner in a corner of the page is easy to miss, and a screen reader won't announce it unless it's in a live region.
