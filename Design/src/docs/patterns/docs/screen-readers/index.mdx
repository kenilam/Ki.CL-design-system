A screen reader turns the page into speech or braille. People move through it element by element, or jump by headings, links, landmarks and form fields. What they hear for each element is built from four things the browser works out from the markup.

## Name, role, state and description

- **Name:** what it's called. It comes from the text inside, a `label`, `alt` or `aria-label`.
- **Role:** what kind of thing it is, from the element: `button`, `a`, `input`, `h2`.
- **State:** what it's doing now: `checked`, `disabled`, `aria-expanded`, `aria-current`.
- **Description:** anything more, from `aria-describedby`, such as a field's hint or error.

A native element sets the role and state itself. `<button disabled>Save</button>` is read by VoiceOver as "Save, button, dimmed" with nothing extra. That's why the design system's components render the real element, and add ARIA where HTML can't express something.

## Name everything

Every control needs a name a person could say out loud, which also helps voice control users, as long as the name includes the visible text.

```tsx
// Read as "Close, button"
<Button aria-label='Close'>
  <Ri.RiCloseLine aria-hidden />
</Button>

// Read as "Your email, edit text": the label names the field
<EmailInput label='Your email' />
```

Icons beside text are decorative, so they get `aria-hidden` and aren't read twice.

## Group and hide

- **Keep what belongs together in one element.** A card with a link in its title is one stop for a screen reader user, rather than one for every line inside it.
- **Hide what repeats.** If something is already said in text, hide the visual copy with `aria-hidden`.
- **Hide visually, not from assistive technology,** with `kicl-hidden`, when a label is only needed by people who can't see the layout.

## Announce what changes

Content that appears without the person moving to it, like a saved message or an error, has to be announced. A live region does that: `role='status'` is read when the reader pauses, `role='alert'` straight away. `Status` uses `status` for information and warnings, and `alert` for errors.

## Leave focus alone, mostly

Let focus follow the page. Move it only when the context changes under the person:

- **On a route change,** move focus to the main content, so the new page is read from the top.
- **When a dialog opens,** focus moves into it. Native `dialog` does this.
- **When it closes,** focus goes back to the control that opened it. Native `dialog` and `popover` do this too.
- **Escape closes** a dialog, sheet or popover that can be closed, and leaves the person where they were.
