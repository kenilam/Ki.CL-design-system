A state tells people what a component is doing or what they can do with it. Each one should be clear without relying on colour, and most of them come from the browser.

## Interaction states

- **Hover** shows something can be used. It's a hint, never the only way to find something, since touch screens and keyboards don't hover.
- **Focus** shows where the keyboard is. It's a dashed outline on `:focus-visible`, so it shows for the keyboard and not for every click.
- **Pressed** confirms the click landed.
- **Selected** or **current** marks the chosen option or the page you're on, with `aria-current='page'` on links.

## Availability

- **Read-only** for a value people should see and copy but not change.
- **Disabled** for a control that doesn't apply right now. It can't be focused, so a screen reader user may never find it. Say why, or leave the control out.
- Inside a form, keep the submit button enabled and explain what's missing instead.

## Content states

- **Loading:** placeholders the shape of the content, so the layout doesn't jump. Mark the area `aria-busy` while it fills.
- **Empty:** say why it's empty and what to do next.
- **Error:** say what went wrong and how to recover. See Feedback and status.
