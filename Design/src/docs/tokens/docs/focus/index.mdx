Someone using the keyboard needs to see where focus is, and the fixed header shouldn't hide what they've moved to.

## Focus ring

Links, buttons, fields, `summary` and `video` draw an outline from three variables. The style is `none` until the element takes keyboard focus, when `:focus-visible` switches it to `dashed`. Clicking a link or button doesn't show the ring, but clicking into a text field does, because the browser expects typing there. Tab always shows it. The colour follows the theme, so the ring keeps its contrast on both.

An element that only script focuses, with `tabindex='-1'`, has no ring. That's how `#main` takes focus after a route change, so a screen reader starts at the new page without a stray outline.

## Out from under the header

The global header is fixed, so the page keeps focus and anchors clear of it:

- `html` sets `scroll-padding-block-start` to the header's height, so a focused field or a jumped-to heading stops below the header, not behind it.
- `:target` adds `scroll-margin-block` of `--kicl-gutter-wide`, so a jump to an anchor never lands flush against that edge.

Neither needs a class. Same-page links scroll smoothly, unless the person asks for less motion.
